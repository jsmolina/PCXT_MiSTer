# PCXT_MiSTer

MiSTer FPGA core emulating an IBM PC/XT compatible system with CGA, HGC, and EGA video adapters.

## Architecture

- **Top-level**: `PCXT.sv` (module `emu`) — MiSTer framework integration
- **Chipset**: `rtl/KFPC-XT/HDL/Chipset.sv` wraps CPU, DMA, PIC, PIT, PPI, peripherals
- **Peripherals**: `rtl/KFPC-XT/HDL/Peripherals.sv` instantiates video (CGA, HGC, EGA), sound, UART, IDE
- **Video**: `rtl/video/` contains CGA, HGC, and EGA subsystems
- **CPU**: `rtl/8088/` — MCL86-based 8088 core
- **Sound**: `rtl/sound/` — OPL (jtopl), SN76489 (jt89), SAA1099

### Video subsystem hierarchy (CGA)

```
Peripherals.sv
  ├── cga cga1             (cga.v)           — CGA card: ISA bus, CRTC, sequencer, pixel pipeline
  │    ├── UM6845R crtc    (UM6845R.v)       — MC6845 CRTC
  │    ├── cga_sequencer   (cga_sequencer.v) — Timing/VRAM read sequencer
  │    └── cga_pixel       (cga_pixel.sv)    — Character ROM, attribute decode, pixel output
  │         └── cga_attrib (cga_attrib.v)    — Foreground/background color, blink, Tandy palette
  ├── cga_vgaport vga_cga  (cga_vgaport.v)  — RGBI to VGA RGB DAC
  └── vram cga_vram        (vram.v)          — Dual-port VRAM (cross-clock-domain bridge)
```

### EGA integration

EGA extends the video subsystem alongside CGA and HGC. The EGA adapter uses:
- I/O base address range `0x3C0–0x3CF` (shared EGA/VGA register space)
- Memory-mapped framebuffer in the `0xA0000–0xAFFFF` range (64KB, 4 bit-planes)
- A CRTC compatible with the MC6845 but with EGA-specific extensions
- An Attribute Controller (AC) for 16-color palette mapping from 64-color DAC
- A Sequencer for memory plane write control and character clock
- A Graphics Controller (GC) for read/write mode logic across bit-planes

EGA files should follow the same structure as CGA: a top-level `ega.v` instantiated from `Peripherals.sv`, with submodules for sequencer, pixel pipeline, attribute controller, and graphics controller.

## HDL languages

| Language        | Usage                                                        |
|-----------------|--------------------------------------------------------------|
| Verilog (.v)    | Video subsystem (CGA, HGC), 8088 CPU, sound cores, sys framework |
| SystemVerilog (.sv) | KFPC-XT chipset, top-level `PCXT.sv`, some video/sound modules |
| VHDL (.vhd)    | UART 16750, ascal scaler, PLL adjust (do not use for new RTL) |

New RTL should use **Verilog (.v)** for video modules (matching CGA/HGC style) or **SystemVerilog (.sv)** for chipset-level integration.

## Coding conventions

### Verilog video modules (CGA/HGC style — use for EGA)

- **Header**: Multi-line `//` comment block with copyright and license
- **`default_nettype`**: Always include `` `default_nettype wire `` before the module
- **Module declaration**: Ports listed inline in the module header, one per line, grouped by function with `//` section comments (Clocks, ISA bus, RAM, Video outputs, etc.)
- **Naming**: `snake_case` for all signals and instances
  - `_l` suffix for active-low signals (e.g., `bus_ior_l`, `ram_we_l`)
  - `_int` suffix for internal/intermediate signals
  - `_synced` suffix for clock-domain-crossed signals
- **Indentation**: 4 spaces (no tabs in video modules)
- **Parameters**: Declared inside the module body with `parameter`. Use `defparam` for CRTC register overrides on instantiation
- **Registers**: Declare with initial values where appropriate (e.g., `reg[7:0] control_reg = 8'b0010_1001;`)
- **Always blocks**: `always @ (posedge clk)` with `begin`/`end`
- **Instantiation**: Named port mapping (`.PORT(signal)`), one port per line, aligned
- **Bit ranges**: No space before bracket (e.g., `input[14:0] bus_a`, not `input [14:0] bus_a`)

### SystemVerilog chipset modules (KFPC-XT style)

- **Module declaration**: ANSI-style with `input logic`, `output logic` type declarations
- **Naming**: `snake_case` for signals, `PascalCase` for module names, `_n` suffix for active-low
- **Indentation**: 4 spaces, well-aligned port connections with padding
- **Types**: Use `logic` throughout
- **Always blocks**: Use `always_comb`, `always_ff @(posedge clock)`

### General rules

- Use `//` comments (never `/* */` block comments)
- Group related signals with blank lines and section comments
- Active-low signals: `_l` in video modules, `_n` in chipset modules
- Clock domain crossings: Use 2-stage flip-flop synchronizers (see `Peripherals.sv` patterns like `cga_io_address_1`/`cga_io_address_2`)
- VRAM: Use dual-port RAM modules (`vram.v`) to bridge clock domains between the chipset bus clock and the video pixel clock
- No `initial` blocks for synthesis (use reset or register initialization)

## Clock domains

- **clk_100**: 100 MHz system/SDRAM clock
- **clk_chipset**: ~4.77 MHz 8088 bus clock (directly from PLL or derived)
- **clk_28_636**: 28.636 MHz — CGA pixel clock (14.318 MHz character clock derived via divider)
- **clk_vga_cga**: VGA-rate CGA output clock
- **clk_vga_hgc**: VGA-rate HGC output clock
- EGA will need a **16.257 MHz pixel clock** (derived from PLL or existing clocks) for standard 640x350 mode

## 8088/XT assembly conventions

When writing x86 assembly for this project (test programs, diagnostics, etc.):

- **Target CPU is 8088** — only use instructions available on the 8088/8086. No 80186+ instructions.
- **Shift/rotate by immediate**: Only `1` is valid (e.g., `shr al, 1`). For shifts > 1, load CL first: `mov cl, 4` / `shr al, cl`.
- **No `pusha`/`popa`**: These are 80186+. Use explicit `push`/`pop` of individual registers.
- **No `push imm`**: `push 0x1234` is 80186+. Use `mov ax, 0x1234` / `push ax`.
- **No `insb`/`outsb`/`insw`/`outsw`**: These are 80186+. Use `in`/`out` with loops.
- **No `enter`/`leave`**: 80186+. Use manual `push bp` / `mov bp, sp` / `pop bp`.
- **No `imul reg, imm`** or 3-operand `imul`: 80186+.
- **No `shl`/`shr`/`rol`/`ror` with immediate > 1**: Always use CL.
- **String instructions**: `rep movsb`, `rep stosb`, `lodsb`, `stosb` etc. are fine.
- **Segment overrides**: Available. `cs:`, `ds:`, `es:`, `ss:`.
- **Assembler**: NASM (`nasm -f bin -o file.com file.asm`), output as DOS .COM files.
